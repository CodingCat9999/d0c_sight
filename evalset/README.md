# 평가셋

**이 디렉터리의 JSON 이 Phase 4~9 전체의 판단 근거다.**

| 파일 | 내용 |
|---|---|
| `postgres-18.json` | 평가 문항 (커밋한다) |
| `human_scores.json` | 사람 채점 결과 (커밋한다) |
| `runs/*.json` | 실행 결과 (커밋하지 않는다 — 재생성 가능) |
| `cache/` | API 응답 캐시 (커밋하지 않는다) |

## 왜 DB 가 아니라 파일인가

버전 관리가 되어야 하고 `git diff` 로 무엇이 바뀌었는지 보여야 한다. 정답 라벨이
언제 왜 바뀌었는지가 평가 결과만큼 중요하다. 공개 문서 기반이라 개인정보 문제도 없다.

## 라벨링

```bash
uv run python tools/labeler/server.py    # http://127.0.0.1:8765
```

## 정답 청크가 썩는 것을 막는 법

각 정답 청크에 본문 해시를 함께 저장한다. 18.4→18.6 실측에서 `chunk_id` 는 100%
유지됐지만 **58개(0.35%)는 id 가 같은데 본문이 바뀌었다.** 존재 확인만으로는 잡히지
않고 라벨이 조용히 틀려진다.

해시가 어긋나면 **자동으로 폐기하지 않는다.** 개정된 문서가 여전히 정답일 수도 있고
아닐 수도 있으며, 그건 기계가 판단할 수 없다. `needs_review` 로 표시하고 사람이
정답 유지 / 라벨 수정 / 문항 폐기 중 하나를 고른다.
